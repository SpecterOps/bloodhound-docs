This page covers configuring the OpenHound Okta collector for your Okta organization.

## Prerequisites

- OpenHound installed with the Okta collector included. The Okta collector is included by default in the OpenHound container image.
  - For BloodHound Community Edition, install the [OpenHound CLI](/openhound/community).
  - For BloodHound Enterprise, [deploy](/openhound/enterprise) OpenHound as a container.
- An Okta account with permissions to access the Okta API. See the options below for recommended roles and permissions.

### OAuth 2.0 Service Application (Recommended)

Register the OpenHound Okta collector as a [service application](/openhound/collectors/okta/okta-app-registration) in Okta.

Grant the application limited read-only permissions and configure authentication with an asymmetric RSA public/private key pair.

### API Token (SSWS)

The OpenHound Okta collector can also authenticate using API tokens (also known as SSWS tokens) associated with specific Okta Super Administrator accounts.
 This is the least secure option, but the easiest one to set up.

## Configure OpenHound

The following OpenHound configuration parameters are required to run the Okta collector. These can either be set
 via the `[sources.source.okta.credentials]` section of the secrets file or via environment variables using the `SOURCES__OKTA__CREDENTIALS` prefix.

### Option 1: Service Application with JSON Key File

Use this option when you prefer to store the Okta private key in a file. Set `private_key_path` to the path of the complete private key JSON that Okta displays when you generate the key pair.

| Parameter Name | Environment Variable | Description |
| --- | --- | --- |
| `base_url` | \{PREFIX\}\_\_BASE\_URL | The base URL of the Okta organization. For example: `https://spectoropspreview.oktapreview.com`. |
| `client_id` | \{PREFIX\}\_\_CLIENT\_ID | The client ID of the Okta service application used to authenticate to the Okta API. |
| `private_key_path` | \{PREFIX\}\_\_PRIVATE\_KEY\_PATH | The path to the private key (.json) used for authentication. |

**Example Configuration**

```toml title="secrets.toml"
[sources.source.okta.credentials]
base_url = "https://<mytenant>.oktapreview.com"
client_id = "<client-id>"
private_key_path = "<path-to-private-key-json>"
```

### Option 2: Service Application with Base64-Encoded JSON Key String

Use this option when you prefer not to store the Okta private key in a standalone file.

| Parameter Name | Environment Variable | Description |
| --- | --- | --- |
| `base_url` | \{PREFIX\}\_\_BASE\_URL | The base URL of the Okta organization. For example: `https://spectoropspreview.oktapreview.com`. |
| `client_id` | \{PREFIX\}\_\_CLIENT\_ID | The client ID of the Okta service application used to authenticate to the Okta API. |
| `private_key_b64` | \{PREFIX\}\_\_PRIVATE\_KEY\_B64 | The private key in JSON format encoded as a base64 string. |

**Example Configuration**

```toml title="secrets.toml"
[sources.source.okta.credentials]
base_url = "https://<mytenant>.oktapreview.com"
client_id = "<client-id>"
private_key_b64 = "<base64-encoded-complete-okta-private-key-json>"
```

Set `private_key_b64` to the base64-encoded contents of the complete private key JSON that Okta displays when you generate the key pair.
 The JSON has the following general structure. The values below are placeholders and are not a usable key.

```json
{
  "kty": "RSA",
  "kid": "<key-id-generated-by-okta>",
  "n": "<public-modulus>",
  "e": "AQAB",
  "d": "<private-exponent>",
  "p": "<first-prime-factor>",
  "q": "<second-prime-factor>",
  "dp": "<first-factor-exponent>",
  "dq": "<second-factor-exponent>",
  "qi": "<first-factor-coefficient>"
}
```

<Warning>
  Keep the complete private key JSON confidential. Okta displays the private key only when you generate it. If you no longer have the JSON, generate and register a new key pair as described in the [Okta app registration guide](/openhound/collectors/okta/okta-app-registration).
</Warning>

### Option 3: API Token (SSWS)

Use this option when you want to authenticate with an API token (SSWS) associated with a specific Okta Super Administrator account.

| Parameter Name | Environment Variable | Description |
| --- | --- | --- |
| `base_url` | \{PREFIX\}\_\_BASE\_URL | The base URL of the Okta organization. For example: `https://spectoropspreview.oktapreview.com`. |
| `token` | \{PREFIX\}\_\_TOKEN | The API token (SSWS) used for authentication. |

**Example Configuration**

```toml title="secrets.toml"
[sources.source.okta.credentials]
base_url = "https://<mytenant>.oktapreview.com"
token = "<api-token>"
```

<Warning>
  We do not recommend this authentication method. However, if you decide to use it, keep the API token confidential.
</Warning>
