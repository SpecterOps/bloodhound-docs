Use the Okta collector to investigate administrative access, application assignments, credentials, and identity relationships in your Okta organization. You can run an interactive collection for BloodHound Community Edition or schedule collections through BloodHound Enterprise.

## Collected data

The collector reads users, groups and memberships, applications and assignments, built-in and custom administrator roles, role assignments and resource sets, API token metadata, OAuth clients, API service integrations, credential metadata, devices, directory agent pools, authorization servers, identity providers, policies, and realms where available.

It also derives relationships from provisioning, delegated authentication, federation, and application configuration. These relationships depend on the evidence returned by Okta and the matching destination objects. An application assignment alone does not prove that a user can bypass the destination's authentication or authorization controls.

## Prerequisites

- An Okta organization and an administrator who can configure a collection identity
- Outbound HTTPS access to the Okta organization
- OpenHound with the Okta collector installed; source installations require Python 3.13 or 3.14
- The matching extension schema installed in your BloodHound instance
- For scheduled collection, a BloodHound Enterprise tenant with OpenHound enabled and an Okta collector client

Use the collector version and extension assets supplied for your beta deployment together. Confirm target compatibility with your beta contact before updating extension assets.

## Collection boundaries

The collector reads Okta APIs. It does not collect Active Directory or Entra ID directly. SharpHound, AzureHound, and other platform collectors provide optional destination context for hybrid investigations. Their identities, tenant boundaries, and collected objects must match the Okta relationship targets; uploading another dataset does not repair denied Okta reads.

Okta features and licenses affect which resources are available. Realm data requires the corresponding Okta entitlement. API authorization depends on both the collection identity and the requested API scopes. A successful login or completed upload does not establish complete coverage.

Application-user and MFA collection can be restricted to reduce request volume. Those options change graph coverage; see [Collect Okta Data](/openhound/collectors/okta/collect-data#collection-options).
