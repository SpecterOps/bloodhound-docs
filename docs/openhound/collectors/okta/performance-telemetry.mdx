Use optional collection performance telemetry to diagnose and tune OpenHound Okta collection performance.

Telemetry is disabled by default and does not change the collection scope, schedule, Okta permissions, or number of Okta requests. When enabled, the collector writes bounded, value-free JSONL diagnostics for endpoint latency, HTTP outcomes, retries, quota observations, concurrency, pacing, pagination, and row counts.

## Configure Telemetry

Add the following section to `config.toml`:

```toml title="config.toml"
[sources.source.okta.telemetry]
enabled = true
output_directory = "./telemetry"
reporting_interval_seconds = 60
max_file_bytes = 10485760
max_interval_records = 1440
queue_capacity = 16
```

Set `output_directory` outside the raw collection output directory. The collector rejects a nested location so the telemetry file is not treated as collection data or uploaded with it.

Run the Okta collection normally. The same configuration applies to interactive, scheduled, and containerized collections. Each collection writes one file named `openhound-okta-<opaque-run-id>.jsonl` in the configured output directory.

## Review Telemetry Records

Each JSONL line is an independently parseable record. The file starts with a `run_start` record, followed by periodic `interval` records, and normally ends with a `run_summary` record. Interrupted or incomplete collections retain records that were flushed before the interruption.

The collector bounds telemetry memory, queue depth, interval records, and file size. If the telemetry destination is unavailable, the exporter fails, or a limit is reached, the collection continues. The diagnostic records indicate dropped records, truncation, or exporter failure; an incomplete telemetry summary does not mean that the Okta collection failed.

## Telemetry Metrics

Telemetry separates the following measurements so you can identify where collection time is spent:

<table style={{ width: "100%", tableLayout: "fixed" }}>
  <colgroup>
    <col style={{ width: "25%" }} />
    <col style={{ width: "75%" }} />
  </colgroup>
  <thead>
    <tr>
      <th>Measurement</th>
      <th>Description</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td><code>http_execution</code></td>
      <td>Measures request execution through response-body transfer. It excludes JSON decoding and downstream DLT row conversion.</td>
    </tr>
    <tr>
      <td><code>slot_wait</code></td>
      <td>Measures time waiting for the Okta endpoint-family concurrency slot.</td>
    </tr>
    <tr>
      <td><code>proactive_pacing_wait</code></td>
      <td>Measures waits caused by pacing against observed quota headers.</td>
    </tr>
    <tr>
      <td><code>retry_backoff_wait</code></td>
      <td>Measures the actual wait before a retry. Retry delay totals are also recorded by retry category.</td>
    </tr>
  </tbody>
</table>

The summary records the effective DLT extraction settings (`extract_workers` and `extract_max_parallel_items`) and the effective Okta performance settings, including page sizes, endpoint concurrency, retry window, and rate-limit reserve.

Page and row counts describe data yielded by Okta pagination; they do not confirm that DLT committed the rows to the raw collection.

<Warning>
  Telemetry uses normalized endpoint templates and excludes credentials, tenant hostnames, raw URLs, cursors, object identifiers, response bodies, profiles, and exception text.

  Store the JSONL files as diagnostic artifacts and do not place them under the raw collection directory.
</Warning>
