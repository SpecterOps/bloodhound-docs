This page covers configuring the OpenHound AWS collector for an AWS account or organization. Use this page to choose a collection strategy and configure the collector settings in the `secrets.toml` file or with environment variables.

## Prerequisites

Before you configure the AWS collector, ensure that the following prerequisites are met:

- [Collector client](/collect-data/enterprise-collection/create-collector) created in BloodHound Enterprise.
- AWS collector permissions [configured](/openhound/collectors/aws/configure-permissions) for the target AWS account or organization.

## Configure OpenHound

The AWS collector needs different settings based on the collection strategy you choose. You can set these values in one of two places:

| Method | Set the values here |
| --- | --- |
| `secrets.toml` file | `[sources.source.aws.credentials]` section |
| Environment variables | `SOURCES__SOURCE__AWS__CREDENTIALS` prefix |

`profile_name` is optional. If you omit it from `secrets.toml` (or leave `SOURCES__SOURCE__AWS__CREDENTIALS__PROFILE_NAME` unset), the collector uses the AWS identity available to its runtime. With a configured source account, that identity must resolve to the account ID in `source_account`. When the management account is the source, the runtime identity must resolve to the management account.

<Warning>
  The beta must use the `openhound-aws` container image from the private ECR repository described in the [beta-only deployment example](/openhound/collectors/aws/collect-data#beta-only). The public `openhound` image does not support AWS collection.
</Warning>

## Choose an account collection strategy

<CollectionStrategy />

Click the tab that matches the strategy of the AWS scope you want to collect.

<Tabs>
  <Tab title="Organization (source account)" icon="star">
    Use this recommended strategy when the collector runs with an AWS identity in a dedicated source account. The configured or runtime identity must resolve to `source_account`.

    | Setting | Required | Default | Description |
    | --- | --- | --- | --- |
    | `profile_name` | No | Runtime identity | Name of the AWS SDK profile used for collection. If omitted, use the identity available to the runtime. |
    | `org_role_name` | Yes | - | Name of the IAM role to assume in each active member account. The collector constructs `arn:aws:iam::<account-id>:role/<org_role_name>`. |
    | `org_role_session_name` | No | `openhound-aws-org-collection` | STS role session name used when assuming organization roles. |
    | `include_management_account` | No | true | Whether to collect account resources from the management account in addition to organization metadata and policies. |
    | `source_account` | Yes | None | Account ID that the configured or runtime AWS identity must resolve to. |
    | `management_account_id` | No | None | Management account ID. If omitted, the source identity must be allowed to call `organizations:DescribeOrganization` so the collector can discover it. |
    | `management_role_name` | No | Value of `org_role_name` | Name of the role assumed in the management account. |

    The collector assumes the management role from the source identity to read AWS Organizations metadata, then assumes the member-account collection role directly from the source identity. Management-account resources are included by default in this mode.

    ```mermaid
    flowchart LR
      SRC["Configured or runtime AWS identity<br/>source_account"]

      subgraph MANAGEMENT["Management account"]
        MROLE["Management role<br/>management_role_name"]
        ORG["Organizations API<br/>accounts, SCPs, and RCPs"]
        MRES["Management account resources<br/>included by default"]
      end

      subgraph MEMBERS["Active member accounts"]
        CHILD1["Member account 1<br/>org_role_name"]
        CHILD2["Member account 2<br/>org_role_name"]
      end

      SRC -->|"AssumeRole: management_role_name"| MROLE
      MROLE --> ORG
      MROLE --> MRES
      SRC -->|"AssumeRole: org_role_name"| CHILD1
      SRC -->|"AssumeRole: org_role_name"| CHILD2
      ORG -. "returns active account IDs" .-> CHILD1
      ORG -. "returns active account IDs" .-> CHILD2
    ```

    The source identity must be allowed to assume the management and member-account roles, and each target role must trust the source identity. If you omit `management_account_id`, the source identity needs `organizations:DescribeOrganization` to discover the management account.

    ```toml title="~/.dlt/secrets.toml"
    [sources.source.aws.credentials]
    profile_name = "security-tooling"
    region_name = "us-east-1"
    source_account = "999999999999"
    management_account_id = "111111111111"
    management_role_name = "ManagementCollectorRole"
    org_role_name = "OpenHoundCollectorRole"
    ```

    `include_management_account` defaults to `true` for this setup. Set it to `false` to omit management-account resources.

    **Environment variables**

    ```bash
    SOURCES__SOURCE__AWS__CREDENTIALS__PROFILE_NAME="security-tooling"
    SOURCES__SOURCE__AWS__CREDENTIALS__REGION_NAME="us-east-1"
    SOURCES__SOURCE__AWS__CREDENTIALS__SOURCE_ACCOUNT="999999999999"
    SOURCES__SOURCE__AWS__CREDENTIALS__MANAGEMENT_ACCOUNT_ID="111111111111"
    SOURCES__SOURCE__AWS__CREDENTIALS__MANAGEMENT_ROLE_NAME="ManagementCollectorRole"
    SOURCES__SOURCE__AWS__CREDENTIALS__ORG_ROLE_NAME="OpenHoundCollectorRole"
    ```
  </Tab>
  <Tab title="Organization (management account)">
    Use this alternative when the collector's AWS identity resolves directly to the AWS organization's management account, reads organization metadata, and assumes `org_role_name` in each active member account.

    | Setting | Required | Default | Description |
    | --- | --- | --- | --- |
    | `profile_name` | No | Runtime identity | Name of the AWS SDK profile used for collection. If omitted, use the identity available to the runtime. The identity must resolve to the management account. |
    | `org_role_name` | Yes | - | Name of the IAM role to assume in each active member account. The collector constructs `arn:aws:iam::<account-id>:role/<org_role_name>`. |
    | `org_role_session_name` | No | `openhound-aws-org-collection` | STS role session name used when assuming organization roles. |
    | `include_management_account` | No | false | Whether to collect account resources from the management account in addition to organization metadata and policies. |

    If a collector runs outside the management account, its AWS profile can use `role_arn` with `source_profile` or `credential_source` to resolve to the management-account role before OpenHound starts. If the configured profile already resolves to the management account, no AWS-profile AssumeRole hop is needed.

    ```toml title="~/.dlt/secrets.toml"
    [sources.source.aws.credentials]
    profile_name = "managementaccount"
    org_role_name = "OpenHoundCollectorRole"
    ```

    `include_management_account` defaults to `false` in this mode. Set it to `true` to collect management-account resources.

    **Environment variables**

    ```bash
    SOURCES__SOURCE__AWS__CREDENTIALS__PROFILE_NAME="managementaccount"
    SOURCES__SOURCE__AWS__CREDENTIALS__ORG_ROLE_NAME="OpenHoundCollectorRole"
    ```
  </Tab>
  <Tab title="Single-account">
    Use a named AWS profile, or omit `profile_name` to use the AWS identity available to the runtime, to collect resources from one AWS account.

    | Setting | Required | Default | Description |
    | --- | --- | --- | --- |
    | `profile_name` | No | Runtime identity | Name of the AWS SDK profile used for collection. If omitted, use the identity available to the runtime. |

    **`secrets.toml`**

    ```toml title="~/.dlt/secrets.toml"
    [sources.source.aws.credentials]
    profile_name = "production"
    ```

    **Environment variables**

    ```bash
    SOURCES__SOURCE__AWS__CREDENTIALS__PROFILE_NAME=production
    ```
  </Tab>
  <Tab title="Multiple independent-accounts">
    Use multiple named AWS profiles to collect resources from multiple independent AWS accounts.

    | Setting | Required | Default | Description |
    | --- | --- | --- | --- |
    | `profile_names` | Yes | None | Names of the AWS SDK profiles used for collection. |

    **`secrets.toml`**

    ```toml title="~/.dlt/secrets.toml"
    [sources.source.aws.credentials]
    profile_names = ["production", "testing"]
    ```

    **Environment variables**

    ```bash
    SOURCES__SOURCE__AWS__CREDENTIALS__PROFILE_NAMES='["production","testing"]'
    ```
  </Tab>
</Tabs>

## Configure S3 collection

S3 bucket collection is disabled by default. Enable it with the `bucket_policy.include` setting, then define bucket and object rules to control which S3 objects the collector stores for processing.

| Setting | Required | Default | Description |
| --- | --- | --- | --- |
| `include` | No | `false` | Enables S3 bucket collection. |
| `max_objects` | No | `10` | Maximum number of objects to collect from each included bucket. Set to `0` to skip object collection. |
| `rule.include` | No | `true` | Includes or excludes matching buckets or objects. Exclusion rules take precedence. |
| `rule.match_bucket` | No | None | Regular expression matched against the S3 bucket name. |
| `rule.match_object` | No | None | Regular expression matched against the S3 object key. |

Buckets and objects are excluded from object collection by default. A bucket or object must match at least one rule where `include` is `true`. If a bucket or object also matches a rule where `include` is `false`, the exclusion wins.

```toml
[sources.source.aws.bucket_policy]
include = true
max_objects = 100

[[sources.source.aws.bucket_policy.rule]]
include = true
match_bucket = "^production.*$"

[[sources.source.aws.bucket_policy.rule]]
include = false
match_bucket = ".*logs.*"

[[sources.source.aws.bucket_policy.rule]]
include = true
match_object = "\\.(json|csv)$"

[[sources.source.aws.bucket_policy.rule]]
include = false
match_object = ".*secret.*"
```

<Note>
  Bucket and object filters apply after AWS API responses are returned. Excluded buckets or objects can still appear in API responses, but the collector does not store excluded objects for further processing.
</Note>

## Configuration examples

The following examples show how to configure the AWS collector for different collection strategies. Replace placeholder values with your own.

### Single-account collection without buckets

```toml 
[destination.bloodhoundenterprise]
token_key = "<BHE_TOKEN_KEY>"
token_id = "<BHE_TOKEN_ID>"
url = "https://your-tenant.bhe.io"

[sources.source.aws.credentials]
profile_name = "<AWS_PROFILE_NAME>"

[sources.source.aws.bucket_policy]
include = false
max_objects = 0
```

### Single-account collection with all buckets

```toml
[destination.bloodhoundenterprise]
token_key = "<BHE_TOKEN_KEY>"
token_id = "<BHE_TOKEN_ID>"
url = "https://your-tenant.bhe.io"

[sources.source.aws.credentials]
profile_name = "<AWS_PROFILE_NAME>"

[sources.source.aws.bucket_policy]
include = true
max_objects = 50

[[sources.source.aws.bucket_policy.rule]]
include = true
match_bucket = ".*"

[[sources.source.aws.bucket_policy.rule]]
include = true
match_object = ".*"
```

### Multiple independent-account collection without buckets

```toml
[destination.bloodhoundenterprise]
token_key = "<BHE_TOKEN_KEY>"
token_id = "<BHE_TOKEN_ID>"
url = "https://your-tenant.bhe.io"

[sources.source.aws.credentials]
profile_names = [
  "<AWS_PROFILE_NAME_1>",
  "<AWS_PROFILE_NAME_2>",
  "<AWS_PROFILE_NAME_3>"
]

[sources.source.aws.bucket_policy]
include = false
max_objects = 0
```

### Organization collection from a configured source account

```toml
[destination.bloodhoundenterprise]
token_key = "<BHE_TOKEN_KEY>"
token_id = "<BHE_TOKEN_ID>"
url = "https://your-tenant.bhe.io"

[sources.source.aws.credentials]
profile_name = "<AWS_SOURCE_PROFILE_NAME>"
source_account = "<AWS_SOURCE_ACCOUNT_ID>"
management_account_id = "<AWS_MANAGEMENT_ACCOUNT_ID>"
management_role_name = "ManagementCollectorRole"
org_role_name = "OpenHoundCollectorRole"
org_role_session_name = "OpenHoundCollectorSession"
include_management_account = true

[sources.source.aws.bucket_policy]
include = false
max_objects = 0
```

### Organization collection from the management account

Use this alternative when the collector's AWS identity resolves to the AWS Organizations management account.

```toml
[destination.bloodhoundenterprise]
token_key = "<BHE_TOKEN_KEY>"
token_id = "<BHE_TOKEN_ID>"
url = "https://your-tenant.bhe.io"

[sources.source.aws.credentials]
profile_name = "<AWS_MANAGEMENT_PROFILE_NAME>"
org_role_name = "OpenHoundCollectorRole"
org_role_session_name = "OpenHoundCollectorSession"
include_management_account = true

[sources.source.aws.bucket_policy]
include = false
max_objects = 0
```

## Deployment examples

Before continuing, ensure that a valid `secrets.toml` file is available and contains the BloodHound Enterprise credentials and optionally AWS profile(s) and bucket collection policies. If `profile_name` is omitted, the collector uses the AWS identity available to its runtime.

<Note>
  The Compose examples assume that the secrets file is stored in the user's home directory at `~/.dlt/secrets.toml`.
</Note>

### BETA ONLY

The `openhound-aws` container image is available from the following private ECR repository:

```text
ec-e7d32cd970094ca9839c97a7c4abb4d2.ecs.us-east-2.on.aws
```

<Note>
  The password to the private container repository will be provided by SpecterOps.
</Note>

<Steps>
  <Step title="Log in to the private repository">
    Configure the Docker CLI to authenticate to the private repository. When prompted for the password, enter the SpecterOps-provided repository password.

    ```bash
    docker login --username ecr-proxy ec-e7d32cd970094ca9839c97a7c4abb4d2.ecs.us-east-2.on.aws
    ```
  </Step>

  <Step title="Pull the OpenHound AWS image">
    Test that you can pull the `openhound-aws` image. You can replace `docker` with `podman` if needed.

    ```bash
    docker pull ec-e7d32cd970094ca9839c97a7c4abb4d2.ecs.us-east-2.on.aws/openhound/openhound-aws:latest
    ```
  </Step>

  <Step title="Create the Docker Compose file">
    Save the following Compose template as a `docker-compose.yaml` file, then run `docker compose up` to start the collector.

    ```yaml title="docker-compose.yaml"
    x-scheduler: &scheduler
      image: ec-e7d32cd970094ca9839c97a7c4abb4d2.ecs.us-east-2.on.aws/openhound/openhound-aws:latest
      restart: unless-stopped
      init: true

      environment: &env
        LOG_LEVEL: INFO
        EXTRACT__WORKERS: 8
        LOG_CONTAINER: true

    services:
      scheduler-aws:
        <<: *scheduler
        environment:
          <<: *env
          DESTINATION__BLOODHOUNDENTERPRISE__COLLECTOR_NAME: aws
          AWS_CONFIG_FILE: /app/.aws/config
          AWS_SHARED_CREDENTIALS_FILE: /app/.aws/credentials

        secrets:
          - source: secrets_aws
            target: /app/.dlt/secrets.toml

          - source: config_aws
            target: /app/.aws/config

          - source: credentials_aws
            target: /app/.aws/credentials

    secrets:
      secrets_aws:
        file: ${HOME}/.dlt/secrets.toml

      config_aws:
        file: ${HOME}/.aws/config

      credentials_aws:
        file: ${HOME}/.aws/credentials
    ```
  </Step>
</Steps>
