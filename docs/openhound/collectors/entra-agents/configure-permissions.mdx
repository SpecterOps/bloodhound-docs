<EntraAgentsBetaNote />

Follow this guide to configure Microsoft Entra for OpenHound Entra Agents data collection.

<Warning>
  Do not add these permissions to an AzureHound application or reuse an AzureHound
  credential. The Entra Agents collector is separate from AzureHound.
</Warning>

## Deployment outcome

Both provisioning routes create the following identity, credentials, and access.

| Component | Created or configured | Details / Access granted |
|---|---|---|
| Collector application and service principal | One single-tenant Entra application registration and its enterprise application | Microsoft Graph application read permissions |
| Collector credential | One app registration client secret | Used by the collector service principal |
| Azure access | Custom Azure RBAC role assigned at the tenant root management group, or selected subscriptions | <a href="/openhound/collectors/entra-agents/assets/openhound-entra-agents-arm-reader-role.json" download="openhound-entra-agents-arm-reader-role.json">OpenHound Entra Agents ARM Reader</a> |
| Foundry agent access | Custom Azure RBAC role assigned at all subscriptions containing Foundry resources or at selected subscriptions | <a href="/openhound/collectors/entra-agents/assets/openhound-entra-agents-foundry-agent-reader-role.json" download="openhound-entra-agents-foundry-agent-reader-role.json">OpenHound Entra Agents Foundry Agent Reader</a> |
| Power Platform access | Tenant-scope Power Platform role assignment to the collector service principal | [Power Platform reader](https://learn.microsoft.com/en-us/power-platform/admin/security/role-based-access-control#built-in-power-platform-roles) |
| [Optional] [Power Platform connector](https://learn.microsoft.com/en-us/connectors/) details | Register the collector service principal as an Power Platform management application | Tenant-wide Power Platform administrator access; enables edges for connection ACL and configured authentications  |
| Environment access | One enabled Dataverse Application User in every approved environment | Custom `OpenHound Entra Agents Dataverse Reader` role |
| Environment inventory† | Administrator-exported and reviewed file | Defines environment inventory the collector needs to collect Power Platform environments |

<Info>
†Environment inventory must manually be exported because the [Power Platform RBAC does not currently support](https://learn.microsoft.com/en-us/power-platform/admin/programmability-extensibility-overview#known-limitations) the `List Environments for User`
endpoint.
</Info>

## Prerequisites

Before you begin, ensure that you have the tools and administrator access below.

- Administrator with permissions to:
  - Create and consent an Entra application
  - Create and assign Azure RBAC roles
  - Assign Power Platform roles
  - Administer each target Dataverse environment, including the **System Administrator** Dataverse role
  - List the Azure subscriptions in scope
- Install [Azure CLI](https://learn.microsoft.com/en-us/cli/azure/install-azure-cli) and [sign in to the target tenant](https://learn.microsoft.com/en-us/cli/azure/authenticate-azure-cli-interactively) with `az login`.
- For automated provisioning, install Bash, Python 3.13 or newer for Foundry role sync.
- [PowerShell](https://learn.microsoft.com/en-us/powershell/scripting/install/installing-powershell) for the environment inventory export.

## Create collector application and assign base permissions

Choose to deploy the base collector application with an automated provisioning script or manually. The later sections describes additional steps which are manual only.

<Tabs>
  <Tab title="Automated provisioning">
    The [provisioning script](/openhound/collectors/entra-agents/assets/provision-identity.sh) deploys a collector service principal,
    its Graph permissions, its Power Platform Reader
    assignment and both custom Azure roles.

    <Steps>
      <Step title="Download the provisioning files">
        Download these files and save them together in the same directory:

        - [provision-identity.sh](/openhound/collectors/entra-agents/assets/provision-identity.sh)
        - [sync-foundry-roles.py](/openhound/collectors/entra-agents/assets/sync-foundry-roles.py)
        - <a href="/openhound/collectors/entra-agents/assets/openhound-entra-agents-arm-reader-role.json" download="openhound-entra-agents-arm-reader-role.json">openhound-entra-agents-arm-reader-role.json</a>
        - <a href="/openhound/collectors/entra-agents/assets/openhound-entra-agents-foundry-agent-reader-role.json" download="openhound-entra-agents-foundry-agent-reader-role.json">openhound-entra-agents-foundry-agent-reader-role.json</a>
      </Step>
      <Step title="Run base provisioning">
        Run the commands below from the directory containing the downloaded files.

        By default, it assigns the <a href="/openhound/collectors/entra-agents/assets/openhound-entra-agents-arm-reader-role.json" download="openhound-entra-agents-arm-reader-role.json">OpenHound Entra Agents ARM Reader</a> role at the tenant root management group and the
        <a href="/openhound/collectors/entra-agents/assets/openhound-entra-agents-foundry-agent-reader-role.json" download="openhound-entra-agents-foundry-agent-reader-role.json">OpenHound Entra Agents Foundry Agent Reader</a> role on enabled subscriptions containing AI Services or OpenAI accounts:

        ```bash
        bash ./provision-identity.sh >> .env
        ```

        To manually set subscription scopes; set the `SUBSCRIPTIONS` variable then run the script:

        ```bash
        SUBSCRIPTIONS="<subscription-id-1> <subscription-id-2>" \
        bash ./provision-identity.sh >> .env
        ```

        This will output an `.env` file containing information and credentials needed for later when [configuring the collector](/openhound/collectors/entra-agents/collect-data).
      </Step>
    </Steps>
  </Tab>
  <Tab title="Manual provisioning">
    Create a dedicated identity for the collector, then grant Microsoft Graph and Azure access. Keep the application client ID, tenant ID, service-principal object ID, and client secret for the remaining steps.

    <Steps>
      <Step title="Create the application">
        Follow Microsoft's [app registration instructions](https://learn.microsoft.com/en-us/entra/identity-platform/quickstart-register-app) to create a dedicated application with these settings:

        - **Name**: `OpenGraph-AZAgents-Collector-ReadOnly`
        - **Supported account types**: Single tenant only
        - **Redirect URI**: Leave empty

        Record the **Application (client) ID** and **Directory (tenant) ID** for [collector configuration](/openhound/collectors/entra-agents/collect-data#configure-the-collector).
      </Step>
      <Step title="Grant Microsoft Graph permissions">
        Follow Microsoft's [application permission instructions](https://learn.microsoft.com/en-us/graph/auth-v2-service#step-1-configure-permissions-for-microsoft-graph) to add the permissions below. Remove the default delegated `User.Read` permission if present; the collector uses application permissions.

        | Permission | Purpose |
        | --- | --- |
        | `Application.Read.All` | Resolve blueprints, applications, credentials, and service principals. |
        | `User.Read.All` | Read agent-user properties. |
        | `RoleManagement.Read.Directory` | List activated directory roles for blueprint credential control. |
        | `AgentIdentity.Read.All` | Read Agent ID identities. |
        | `AgentIdentityBlueprint.Read.All` | Read Agent ID blueprints. |
        | `AgentIdentityBlueprintPrincipal.Read.All` | Read blueprint principals. |
        | `AgentCollection.Read.All` | Read Agent Registry collection metadata. |
        | `AgentInstance.Read.All` | Read Agent Registry instance metadata. |

        [Grant administrator consent](https://learn.microsoft.com/en-us/graph/auth-v2-service#step-2-request-administrator-consent) for the configured permissions and confirm that consent is granted for each one.
      </Step>
      <Step title="Create and safely store a collector credential">
        Follow Microsoft's [credential instructions](https://learn.microsoft.com/en-us/entra/identity-platform/how-to-add-credentials) to create a client secret with an expiry that matches your rotation policy. Securely store the secret **Value** for [collector configuration](/openhound/collectors/entra-agents/collect-data#configure-the-collector); the secret ID cannot be used for authentication.
      </Step>
      <Step title="Inspect the enterprise application">
        Record the collector enterprise application's [Object ID](https://learn.microsoft.com/en-us/entra/identity/enterprise-apps/application-properties#object-id). This is the service-principal object ID used for Azure and Power Platform role assignments. It differs from both the application client ID and the app registration's object ID.
      </Step>
      <Step title="Create and assign the custom ARM role">
        Download the <a href="/openhound/collectors/entra-agents/assets/openhound-entra-agents-arm-reader-role.json" download="openhound-entra-agents-arm-reader-role.json">OpenHound Entra Agents ARM Reader template</a> and replace `<tenantRootGroupId>` with the tenant root management group ID in:

        ```json
        "assignableScopes": [
          "/providers/Microsoft.Management/managementGroups/<tenantRootGroupId>"
        ],
        ```

        Follow Microsoft's [custom role instructions](https://learn.microsoft.com/en-us/azure/role-based-access-control/custom-roles-portal) to create the role from the JSON template. Then [assign the role](https://learn.microsoft.com/en-us/azure/role-based-access-control/role-assignments-portal) to the collector service principal at the tenant root management group for tenant-wide ARM collection, or at each selected subscription to limit collection scope.
      </Step>
      <Step title="Create and assign the custom Foundry role">
        Download the <a href="/openhound/collectors/entra-agents/assets/openhound-entra-agents-foundry-agent-reader-role.json" download="openhound-entra-agents-foundry-agent-reader-role.json">OpenHound Entra Agents Foundry Agent Reader template</a> and replace `<subscriptionId>` with an in-scope subscription ID:

        ```json
        "assignableScopes": [
          "/subscriptions/<subscriptionId>"
        ],
        ```

        If multiple subscriptions are in scope, include an entry for each:

        ```json
        "assignableScopes": [
          "/subscriptions/<subscriptionId1>",
          "/subscriptions/<subscriptionId2>"
        ],
        ```

        Follow Microsoft's [custom role instructions](https://learn.microsoft.com/en-us/azure/role-based-access-control/custom-roles-portal) to create the role from the JSON template. Then [assign the role](https://learn.microsoft.com/en-us/azure/role-based-access-control/role-assignments-portal) to the collector service principal at every in-scope subscription containing AI Services or OpenAI accounts.
      </Step>
      <Step title="Assign Power Platform Reader to the collector application">
        Assign the built-in Power Platform **Reader** role to the collector service
        principal. The administrator performing this step needs Power Platform
        Administrator or Power Platform role-based access-control administrator rights.

        Sign in to the Azure CLI in PowerShell, then run the code below after changing the `<TENANT ID>` and `<ENTERPRISE APPLICATION OBJECT ID>`:

        ```powershell
        $tenantId = "<TENANT ID>"
        $enterpriseApplicationObjectId = "<ENTERPRISE APPLICATION OBJECT ID>"

        # Power Platform Reader GUID https://learn.microsoft.com/en-us/power-platform/admin/security/role-based-access-control#built-in-power-platform-roles
        $powerPlatformReaderId = "c886ad2e-27f7-4874-8381-5849b8d8a090"

        $ppApiToken = az account get-access-token `
        --resource https://api.powerplatform.com --query accessToken -o tsv
        $headers = @{ Authorization = "Bearer $ppApiToken"; "Content-Type" = "application/json" }

        $body = @{
        principalObjectId = $enterpriseApplicationObjectId
        principalType = "ApplicationUser"
        roleDefinitionId = $powerPlatformReaderId
        scope = "/tenants/$tenantId"
        } | ConvertTo-Json

        Invoke-RestMethod -Method Post `
        -Uri "https://api.powerplatform.com/authorization/roleAssignments?api-version=2024-10-01" `
        -Headers $headers -Body $body
        ```
      </Step>
    </Steps>
  </Tab>
</Tabs>

## Optional connection detail and sharing visibility

This is an optional step that will allowing the collector to read [Power Platform connection](https://learn.microsoft.com/en-us/connectors/) details by registering the collector as an management application.

See [collector-limitations](/openhound/collectors/entra-agents/collector-limitations#connection-sharing-and-credential-details-require-higher-collector-permissions) for more details and visibility benefits.

<Info>
  [Microsoft states](https://learn.microsoft.com/en-us/power-platform/admin/powershell-create-service-principal#limitations-of-service-principals)
  that a Power Platform management application has Power Platform administrator-equivalent
  capabilities and cannot be limited with granular roles. Those capabilities
  include changing and deleting Power Platform resources.
</Info>

To enable these reads, a Power Platform administrator must register the collector application as a [Power Platform management application](https://learn.microsoft.com/en-us/power-platform/admin/powershell-create-service-principal#registering-an-admin-management-application):

<Steps>
  <Step title="Prepare the administrator session">
    Install the [Power Apps administration PowerShell module](https://learn.microsoft.com/en-us/powershell/powerapps/get-started-powerapps-admin).
  </Step>
  <Step title="Register the management application">
    Set `$collectorClientId` to the collector's **Application (client) ID**, then run the command and sign in with an administrator account:

    ```powershell
    New-PowerAppManagementApp -ApplicationId $collectorClientId
    ```
  </Step>
</Steps>

The collector always attempts Power Apps administrator connection and role-assignment
reads in each configured environment. Without this optional registration, a
an informational coverage message will be logged.

## Export and maintain the environment inventory

The assigned Power Platform Reader role does not allow the collector service
principal to list environments due to a [limitation with the Power Platform API
and RBAC](https://learn.microsoft.com/en-us/power-platform/admin/programmability-extensibility-overview#known-limitations).
An administrator must therefore create and review the inventory used by the
collector.

The collector tries the Power Platform API first, then this environment inventory, and lastly a legacy BAP discovery fallback that requires [Power Platform management-app registration](https://learn.microsoft.com/en-us/power-platform/admin/powershell-create-service-principal),
which Microsoft states gives the application the same permissions as a tenant
administrator and cannot be limited with granular roles. The legacy BAP fallback is therefore not recommended.

### Export the environment inventory

Use an administrator session to export the environments, then review the file before providing it to the collector.

<Steps>
  <Step title="Sign in as an administrator">
    Sign in with a different Azure CLI scope as an administrator:

    ```powershell
    $tenantId = "<TENANT ID>"
    az login --tenant $tenantId --scope https://api.powerplatform.com/.default
    ```
  </Step>
  <Step title="Export the inventory">
    Download [export-power-platform-environments.ps1](/openhound/collectors/entra-agents/assets/export-power-platform-environments.ps1). From the directory containing the downloaded script, create the `.dlt` output directory and export the inventory to `.dlt/power-platform-environments.json`:

    ```powershell
    New-Item -ItemType Directory -Path .dlt -Force | Out-Null
    ./export-power-platform-environments.ps1 -OutputPath .dlt/power-platform-environments.json
    ```
  </Step>
  <Step title="Review the collection scope">
    Review the inventory and if an Azure role assignment scope was set remove environments outside
    the scope.
  </Step>
</Steps>

### Refresh the inventory after scope changes

Refresh the inventory manually or by running the script every time an environment is onboarded,
offboarded, renamed, gains Dataverse, or otherwise changes collection scope.

Also [configure the application for each newly approved Dataverse environment](#configure-the-application-for-each-dataverse-environment) before using the refreshed inventory.

## Configure the application for each Dataverse environment

Complete these steps for each approved Dataverse environment in the inventory. The application user and its read-only role provide the collector with access to that environment.

<Steps>
  <Step title="Confirm operator access">
    The administrator creating the Application User needs **System Administrator**
    inside each target Dataverse environment. Tenant Global Administrator and Power
    Platform Administrator alone do not provide the Dataverse `prvCreateUser`
    privilege.
  </Step>
  <Step title="Create an Application User">
    Follow Microsoft's [application user instructions](https://learn.microsoft.com/en-us/power-platform/admin/manage-application-users#create-an-application-user) to create an enabled application user for the collector in this environment. Select the collector's **Application (client) ID** and the appropriate business unit.
  </Step>
  <Step title="Create a custom Dataverse reader role">
    Follow Microsoft's [custom security role instructions](https://learn.microsoft.com/en-us/power-platform/admin/database-security-configure) to create a role named `OpenHound Entra Agents Dataverse Reader`.

    Grant **Read** at **Organization** scope on the tables below. Leave **Include App Opener privileges** unchecked, and do not grant Create, Write, Delete, Append, Append To, Assign, or Share privileges.

    | Table | Logical name |
    | --- | --- |
    | Agent or Bot | `bot` |
    | Agent component or Bot Component | `botcomponent` |
    | Connection | `connection` |
    | Connection Reference | `connectionreference` |
    | Process | `workflow` |
    | User | `systemuser` |
    | Team | `team` |
  </Step>
  <Step title="Assign the custom Dataverse reader role">
    Follow Microsoft's [application user role instructions](https://learn.microsoft.com/en-us/power-platform/admin/manage-application-users#manage-roles-for-an-application-user) to assign `OpenHound Entra Agents Dataverse Reader` to the collector application user. Confirm that the user is enabled and the role is assigned in this environment.
  </Step>
</Steps>

## Ongoing operation

Keep permissions and the environment inventory aligned with the collection scope as it changes.

- Refresh and review the environment inventory.
- Add the application and grant it the custom Dataverse role on new environments.
- Add new subscriptions with AI Services or OpenAI accounts to the custom Azure roles. You can use the
  [Foundry role sync](/openhound/collectors/entra-agents/assets/sync-foundry-roles.py) script to automate it: run `python ./sync-foundry-roles.py` from the directory containing the downloaded Python script and both JSON role files. The command
  previews assignments; rerun with `--apply` to add them. If `SUBSCRIPTIONS`
  limits collection, assign the ARM role at the new subscription too and include
  it in `SUBSCRIPTIONS` when running the sync. Set `AZ_AGENTS_SP_OBJECT_ID` to
  select a different service principal. Remove existing assignments separately
  when a subscription leaves scope.

## Troubleshooting

Use provisioning and access errors to identify missing administrator privileges or role assignments. For inventory configuration, missing results, or device-code prompts, see [collection troubleshooting](/openhound/collectors/entra-agents/collect-data#troubleshooting).

| What you see | What to check |
|---|---|
| `403 0x80072560` from Dataverse | The Application User is absent, disabled, registered for the wrong application, or missing its read-only role. |
| `0x80040220` while creating the Application User | The operator lacks Dataverse System Administrator in that environment. |
| ARM returns `403` | Recheck the custom ARM role at the tenant root or each approved subscription. |
| Foundry agent list returns `403` | Recheck the `OpenHound Entra Agents Foundry Agent Reader` assignment at the relevant subscription. |
| Foundry role sync cannot list accounts | Confirm the signed-in Azure CLI identity can read the selected subscriptions and list accounts. Set `SUBSCRIPTIONS` to bypass discovery and assign at the IDs supplied. |
