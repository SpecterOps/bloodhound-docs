With Hunter, AI agents can help prioritize active findings, check collection health, investigate risky relationships and reachable objects, surface bounded attack paths, and summarize evidence with remediation guidance.

Your AI agents can connect to BloodHound Hunter MCP as a remote streamable HTTP server with no local installation required. BloodHound Hunter is currently available in a limited closed Beta and must be enabled for your BloodHound Enterprise tenant.

## Requirements

- A BloodHound Enterprise deployment with the BloodHound Hunter beta enabled
- A supported MCP client approved for use with your BloodHound data
- Outbound HTTPS access from the selected client to your BloodHound Enterprise tenant
- A BloodHound Enterprise account with the `User`, `Power User`, or `Administrator` role

## Connect an MCP client

Your Hunter MCP server URL is:

```text
https://<bloodhound-host>/api/v2/hunter/mcp
```

Replace `<bloodhound-host>` with your BloodHound Enterprise tenant domain. Hunter publishes OAuth discovery metadata and supports dynamic client registration, so you do not need to create a Connected App or provide a client secret.

Configure the Hunter URL as a remote MCP server by following the documentation for your client:

- [OpenAI Codex MCP documentation](https://developers.openai.com/codex/mcp/)
- [Claude.ai and Claude Desktop custom connector documentation](https://claude.com/docs/connectors/custom/add-unlisted)
- [Claude Code MCP documentation](https://code.claude.com/docs/en/mcp#authenticate-with-remote-mcp-servers)
- [GitHub Copilot and VS Code MCP server documentation](https://code.visualstudio.com/docs/agent-customization/mcp-servers)
- [OpenCode MCP server documentation](https://opencode.ai/docs/mcp-servers/#oauth)

## Approve and verify the connection

<Steps>
  <Step title="Approve access in BloodHound">
    Sign in to BloodHound Enterprise if necessary. Review the **Requesting client** and **Callback URL**, then select **Approve Hunter Access**.
  </Step>
  <Step title="Verify Hunter in your client">
    Start or return to a chat and enter:

    <Prompt description="Verify the Hunter MCP connection">
    Call `bloodhound_status`, confirm that Hunter is authenticated, and summarize the available capabilities without querying BloodHound data yet.
    </Prompt>
  </Step>
</Steps>

## Workflow example

Enter the following prompt in your connected client to get a BloodHound environment and risk overview.

<Prompt description="Get started with Hunter MCP">
Use Hunter to list the BloodHound environments I can access, summarize their collection health and warnings, and then execute the bloodhound-top-findings prompt for the highest-priority active findings. For the top three findings, explain the ranking, show bounded evidence, and provide the short canonical remediation.
</Prompt>

<Info>Hunter directs clients to use its typed tools first, retain the identifiers returned by the server, and avoid raw Cypher unless the typed tools cannot answer the question.</Info>

## Additional prompts to try

1. Review your highest-severity findings with reasoning and remediation steps.
    <Prompt description="Prioritize Findings">
    Show my highest-priority active findings, explain why they rank highly, and give me the short remediation for the top three.
    </Prompt>
2. Dig into the details of a specific finding and receive the remediation steps.
    <Prompt description="Investigate a specific finding">
    Investigate finding ID `<finding-id>`, explain any proven current graph relationship, and summarize remediation for a security operator. Ask me which finding `<finding-id>` to investigate.
    </Prompt>
3. Get a pulse on how your collectors are performing and if any are in need of review.
    <Prompt description="Check collection coverage">
    List my visible AD, Azure, and OpenGraph environments and summarize collection health, stale data, and completeness warnings
    </Prompt>
4. Investigate a specific object and the attack paths within a certain number of hops.
    <Prompt description="Analyze control and reachability">
    Find the risky inbound control relationships for `<object>`, then show what is reachable within two hops. Ask me which `<object>` to evaluate.
    </Prompt>
5. Generate a shareable link that includes attack paths between a source and a target object.
    <Prompt description="Find and visualize an attack path">
    Find bounded shortest attack paths from `<source-id>` to `<target-id>` and create a BloodHound Explore link for the best verified path. Ask me for the `<source-id>` and `<target-id>`.
    </Prompt>

## Manage access

In BloodHound Enterprise, select **Hunter MCP** to manage access associated with your account:

- **Connected Apps** lists manually created and automatically registered MCP clients. Deleting an app disconnects all of its active connections.
- **Active Connections** lists your current authorizations and their expiration dates. Revoking a connection immediately disconnects that client.

After deleting an app or revoking a connection, repeat the authentication steps in your MCP client to reconnect.

## Troubleshoot a connection

- **Authorization unavailable:** Return to your MCP client and start authentication again. Authorization requests expire after 10 minutes and cannot be reused.
- **Tools unavailable after approval:** Check the MCP server status in your client and reconnect it if necessary.
- **Persistent `401 Unauthorized`:** Authenticate again, then check **Hunter MCP > Active Connections** to confirm that the connection exists and has not expired or been revoked. 
- **`404 Not Found`:** Confirm that the beta is enabled for your tenant and that the server URL ends in `/api/v2/hunter/mcp`.
