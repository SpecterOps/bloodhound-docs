With Hunter, AI agents can help prioritize active findings, check collection health, investigate risky relationships and reachable objects, surface bounded attack paths, and summarize evidence with remediation guidance.

Your AI agents can connect to BloodHound Hunter MCP as a remote streamable HTTP server with no local installation required. BloodHound Hunter is currently available in a limited closed Beta and must be enabled for your BloodHound Enterprise tenant.

## Requirements
- A BloodHound Enterprise deployment with the BloodHound Hunter beta enabled.
- An active OpenAI Codex subscription approved for use with your BloodHound data.
- Codex in the ChatGPT desktop app, CLI, or IDE extension, with outbound HTTPS access to your BloodHound Enterprise tenant.
- An active BloodHound session within your browser.
- Account used for authentication with Hunter MCP server must have one of the following BloodHound Enterprise roles: User, Power User, or Administrator.

## Connect Codex to Hunter
1. Start a new Codex chat and enter the prompt below to connect to Hunter MCP.
    <Prompt description="Connect to Hunter MCP">
    Connect to the MCP server at `https://<bloodhound-host>/api/v2/huntmaster/mcp` and execute the bloodhound-login prompt presented by the MCP server. Ask me to provide the BloodHound tenant domain to replace `<bloodhound-host>` to be used for this connection.
    </Prompt>
2. Codex will present a login URL and a one-time code within your chat window. Open the link in your preferred browser. Sign into BloodHound if necessary, confirm that the page’s code matches the code Codex displayed, and approve access.
3. Return to the same Codex chat. Codex will poll for approval and refresh Hunter's tools and resources without opening a new MCP transport.
4. Ask Codex to verify the connection:
    <Prompt description="Verify the Hunter MCP connection">
    Call `bloodhound_status`, confirm that Hunter is authenticated, and summarize the available capabilities without querying BloodHound data yet.
    </Prompt>


<Info>If Codex saves the server but does not expose its tools, restart Codex (or the IDE extension) and repeat the connection prompt.</Info>

## Codex Workflow Example
Enter the following prompt into OpenAI Codex to get started with a BloodHound environment and risk overview.
<Prompt description="Get started with Hunter MCP">
Use Hunter to list the BloodHound environments I can access, summarize their collection health and warnings, and then execute the bloodhound-top-findings prompt for the highest-priority active findings. For the top three findings, explain the ranking, show bounded evidence, and provide the short canonical remediation.
</Prompt>
<Info>Codex uses the typed Hunter tools first, retains the identifiers returned by the server, and avoids raw Cypher unless the typed tools cannot answer the question.</Info>

## Additional Prompts to Try in Codex
1. Review your highest-severity findings with reasoning and remediation steps.
    <Prompt description="Prioritize Findings">
    Show my highest-priority active findings, explain why they rank highly, and give me the short remediation for the top three.
    </Prompt>
2. Dig into the details of a specific finding and receive the remediation steps.
    <Prompt description="Investigate a specific finding">
    Investigate finding ID `<finding-id>`, explain any proven current graph relationship, and summarize remediation for a security operator. Ask me which finding `<finding-id>` to investigate.
    </Prompt>
3. Get a pulse on how your collectors are performing and if any are in need of review.
    <Prompt description="Check collection coverage">
    List my visible AD, Azure, and OpenGraph environments and summarize collection health, stale data, and completeness warnings
    </Prompt>
4. Investigate a specific object and the attack paths within a certain number of hops.
    <Prompt description="Analyze control and reachability">
    Find the risky inbound control relationships for `<object>`, then show what is reachable within two hops. Ask me which `<object>` to evaluate.
    </Prompt>
5. Generate a shareable link that includes attack paths between a source and a target object.
    <Prompt description="Find and visualize an attack path">
    Find bounded shortest attack paths from `<source-id>` to `<target-id>` and create a BloodHound Explore link for the best verified path. Ask me for the `<source-id>` and `<target-id>`.
    </Prompt>

## Known Restrictions and Operational Limits
<table>
  <thead>
    <tr>
      <th>Area</th>
      <th>Current behavior</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td><strong>Authentication model</strong></td>
      <td>
        <ul>
          <li>Hunter uses its own browser-approval flow; it is not an OAuth 2.0 authorization server. Do not use Codex’s built in MCP login feature for Hunter.</li>
        </ul>
      </td>
    </tr>
    <tr>
      <td><strong>Login and session lifetime</strong></td>
      <td>
        <ul>
          <li>When authenticating, one-time codes expire after 10 minutes.</li>
          <li>Sessions expire after 30 minutes of inactivity.</li>
          <li>Sessions expire after 8 hours after login even when active.</li>
          <li>Logging out of BloodHound in your browser or a change in user permissions during an active session requires reauthentication.</li>
        </ul>
      </td>
    </tr>
    <tr>
      <td><strong>MCP Catalog compatibility</strong></td>
      <td>
        <ul>
          <li>When unauthenticated, Hunter MCP only presents you with the option to check the current status or start a new session by authenticating.</li>
          <li>If authenticated and your capabilities are still limited, ask Codex to refresh Hunter’s tools and resources within the same chat.</li>
        </ul>
      </td>
    </tr>
    <tr>
      <td><strong>Result format</strong></td>
      <td>
        <ul>
          <li>Hunter returns full tool results as structured data that Codex can inspect, filter, and summarize. The visible text response from the tool is only a brief status message.</li>
        </ul>
      </td>
    </tr>
    <tr>
      <td><strong>Rate and capacity limits</strong></td>
      <td>
        <ul>
          <li>Shared HTTP limit is 55 requests/second per client IP per API process.</li>
          <li>Accounts are limited to 10 concurrent connections.</li>
          <li>Rate limiting is indicated by a HTTP 429 error.</li>
        </ul>
      </td>
    </tr>
    <tr>
      <td><strong>Request and response budgets</strong></td>
      <td>
        <ul>
          <li>Request bodies are limited to 2 MiB and must be read within 15 seconds.</li>
          <li>Large results may be paginated or summarized.</li>
          <li>Most data/graph work has a server-owned 30-second deadline; broad queries fail rather than running indefinitely.</li>
        </ul>
      </td>
    </tr>
    <tr>
      <td><strong>Read-only</strong></td>
      <td>
        <ul>
          <li>All advertised data operations are read-only.</li>
        </ul>
      </td>
    </tr>
    <tr>
      <td><strong>Cypher Query Limits</strong></td>
      <td>
        <ul>
          <li>Requires a terminal literal LIMIT from 1&ndash;100.</li>
          <li>Bounds variable traversal to 10 hops (at most).</li>
          <li>Rejects mutations and collection-producing result functions.</li>
          <li>Unavailable to Environment Targeted Access Control (ETAC)-restricted users. Typed tools remain available to those users and enforce ETAC before graph work.</li>
        </ul>
      </td>
    </tr>
    <tr>
      <td><strong>Explore links</strong></td>
      <td>
        <ul>
          <li>Generated Explore URLs contain graph identifiers but no credentials. To view an Explore link, the user is required to authenticate with an active BloodHound Enterprise account with the necessary permissions. A link’s existence does not prove that the path still exists.</li>
        </ul>
      </td>
    </tr>
    <tr>
      <td><strong>Static remediation content</strong></td>
      <td>
        <ul>
          <li>Hunter retrieves the remediation guidance embedded in the BloodHound Enterprise product.</li>
        </ul>
      </td>
    </tr>
  </tbody>
</table>
