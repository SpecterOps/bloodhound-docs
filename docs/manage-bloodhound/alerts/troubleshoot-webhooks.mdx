Use **Event History** and your webhook receiver logs to diagnose delivery failures. Do not share the HMAC secret while troubleshooting.

## Confirm that an event is expected

BloodHound triggers **Collector Offline** only after a collector has not checked in for at least 20 minutes. It evaluates collector status about every seven minutes, so delivery normally begins about 20 to 27 minutes after the last check-in.

BloodHound sends at most one Collector Offline event for each collector during a seven-day cooldown. It does not send a recovery event when that collector checks in again.

## Review Event History

Go to **Administration** > **Alerts** > **Event History**, then search for the event ID or open **View Event History** from the webhook actions menu.

Use the delivery information to identify where the failure occurred:

| Signal | What to check |
| --- | --- |
| No event | Confirm Alerts is enabled, the rule uses **Collector Offline**, and the collector has exceeded the offline threshold. |
| Last error | Check the receiver address, its TLS certificate, network reachability, and application logs. |
| Next attempt | BloodHound has scheduled another delivery attempt. |
| Attempts | A count that increases after failed delivery attempts. |
| Successful time | The receiver returned a 2xx response. |

The [delivery attempt API reference](/reference/alerts/list-alert-attempts) includes additional fields, such as the last HTTP status code and a manual retry endpoint.

## Resolve common failures

| Problem | Resolution |
| --- | --- |
| The webhook is unavailable | Confirm the endpoint is reachable from BloodHound and has a valid TLS 1.2 or later certificate. |
| The receiver returns a non-2xx response | Review the receiver error and return a 2xx response only after the event is accepted. BloodHound treats redirects as failures. |
| Signature verification fails | Verify the receiver uses the current secret, the raw request body, and the timestamp from `X-Bloodhound-Signature`. See [verify webhook signatures](/integrations/webhooks/collector-offline#verify-the-signature). |
| The secret is lost or exposed | Regenerate the secret in **Delivery**, update the receiver, and disable the webhook until the new secret is active. |
| A receiver processes the same event more than once | Deduplicate by `X-Bloodhound-Event-ID` or the payload `event_id`. BloodHound can retry a failed delivery. |

## Collect safe escalation details

When you contact support, provide the webhook name, event ID, timestamp, HTTP status code, and sanitized receiver error. Do not provide the HMAC secret or a payload containing sensitive environment data unless your support process explicitly authorizes it.
