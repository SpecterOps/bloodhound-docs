Configure a webhook destination and then create a rule that sends Collector Offline events to it. Before you start, [enable Alerts](/manage-bloodhound/alerts/overview#enable-alerts) and prepare a receiver that accepts HTTPS POST requests and validates BloodHound signatures.

## Before you begin

- You have the `AlertsManage` permission.
- Your receiver has an HTTPS URL and supports TLS 1.2 or later.
- Your receiver returns a 2xx response after it accepts an event.
- You have a secure location to store the HMAC secret. BloodHound displays it only when you create or rotate a webhook.

## Create a webhook destination

<Steps>
  <Step title="Open Delivery">
    Go to **Administration** > **Alerts** > **Delivery**.
  </Step>

  <Step title="Create the webhook">
    Select **Create**. In **Create New Webhook**, enter a name, optional description, and your HTTPS endpoint URL. The only supported type is **Generic**.
  </Step>

  <Step title="Store the HMAC secret">
    Select **Create**. Copy the HMAC secret from the confirmation dialog and store it in your secret manager before you close the dialog.

    BloodHound does not display this secret again. If you lose it, regenerate the secret and update your receiver immediately.
  </Step>
</Steps>

## Test the destination

Use **Run Test** from the webhook's actions menu before you create a production rule.

1. Select **Run Test** for the webhook.
1. Select **Collector Offline** and version **1**.
1. Select **Run**.
1. Confirm that your receiver accepted the signed request and that BloodHound reports a successful test. If the receiver rejects or cannot receive the request, use the reported status code and error to diagnose the receiver.

The test sends a representative event to the destination. Use the [webhook reference](/integrations/webhooks/collector-offline) to validate the headers, payload, and signature.

A test does not create an Event History record, increase a delivery attempt count, or affect webhook health. BloodHound returns the test result even when the receiver returns a non-2xx response.

## Create a Collector Offline rule

<Steps>
  <Step title="Open Rules">
    Go to **Administration** > **Alerts** > **Rules**.
  </Step>

  <Step title="Create a notification">
    Select **Create**. In **Create New Notification**, enter a name and, if useful, a description.
  </Step>

  <Step title="Select the destination and event">
    Select your webhook, select **Collector Offline** as the **Event Trigger**, and select version **1**.
  </Step>

  <Step title="Save the rule">
    Select **Create**. BloodHound sends an event to the selected webhook when a collector meets the offline condition.
  </Step>
</Steps>

## Manage a webhook

Use a webhook's actions menu in **Delivery** to manage it.

- **Edit** changes the name, description, or endpoint URL.
- **Disable Webhook** stops deliveries without deleting its configuration. Select **Enable Webhook** to resume delivery. Re-enabling a webhook resets its delivery health.
- **Regenerate Secret** replaces the current HMAC secret. Update your receiver before you resume normal delivery.
- **Delete** permanently removes the destination and its associated delivery history.
- **View Event History** opens delivery attempts for that webhook.

BloodHound calculates delivery health from webhook dispatch outcomes. It automatically disables a webhook when its health falls below `0.5`. Review and correct the receiver before you re-enable the webhook.

<Warning>
Treat the endpoint URL and payload as sensitive operational data. Limit access to the destination, use a dedicated secret for each webhook, and never include the HMAC secret in a ticket, log, or support request.
</Warning>
