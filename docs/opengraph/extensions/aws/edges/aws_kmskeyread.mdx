Principal has all KMS key cryptographic operation permissions (Decrypt + Encrypt + GenerateDataKey).

## Edge schema

| Source kind | Destination kind |
| --- | --- |
| [AWS_Role](/opengraph/extensions/aws/nodes/aws_role) | [AWS_KMSKey](/opengraph/extensions/aws/nodes/aws_kmskey) |
| [AWS_User](/opengraph/extensions/aws/nodes/aws_user) | [AWS_KMSKey](/opengraph/extensions/aws/nodes/aws_kmskey) |

**Traversable:** No. This relationship supplies structural or permission evidence and does not independently form an Attack Path step.

## Composite requirements

The collector combines the following permission kinds for the same principal and target. Their presence must satisfy the collector's evaluation and resource-state checks.

- [AWS_CanDecryptKMSKey](/opengraph/extensions/aws/edges/aws_candecryptkmskey)
- [AWS_CanEncryptKMSKey](/opengraph/extensions/aws/edges/aws_canencryptkmskey)
- [AWS_CanGenerateKMSDataKey](/opengraph/extensions/aws/edges/aws_cangeneratekmsdatakey)

## Evaluation limits

This edge represents the collector's model of collected authorization and resource state. It does not prove that every runtime request succeeds. Inspect unresolved `conditions` and `trust_policy_conditions` when present; `has_conditions` and `has_trust_policy_conditions` indicate retained evidence. Composite edges can include `methods` or `composite_components` describing their derivation.
