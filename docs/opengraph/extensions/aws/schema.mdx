The AWS extension models accounts, IAM identities, resources, and their authorization relationships. Use this reference to interpret the graph produced by the [AWS collector](/openhound/collectors/aws/overview).

## Metadata

| Field | Value |
| --- | --- |
| name | `SOAWS` |
| display_name | `AWS` |
| version | `v0.0.4` |
| namespace | `AWS` |
| Environment kind | `AWS_Account` |
| Platform (`source_kind`) | `AWS` |

This unreleased integration reference contains **22 node kinds** and **169 edge kinds**: **36 traversable** and **133 non-traversable**. It does not establish compatibility with a released BloodHound version.

## How to read the schema

Edge direction runs from the source node to the destination node. Traversable edges can participate in Attack Paths; non-traversable edges retain structural or permission evidence. An IAM allow statement alone does not establish an unconditional Attack Path. The collector evaluates policies and can retain unresolved conditions on edges. Review the edge detail page and collected evidence before interpreting a capability.

Creation capabilities can end at an account because the resource does not exist yet. S3 object-operation edges can end at a bucket to describe its modeled object namespace, or at a collected object; a bucket endpoint does not assert access to every key.
