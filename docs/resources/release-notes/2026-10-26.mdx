<Update label="BloodHound" description="New Feature" tags={["OpenGraph"]}>
  {/*BED-9897, BED-9497, BED-9498, BED-9322, BED-9319*/}
  ## Extension bundles

  An extension bundle packages an OpenGraph extension's schema with supported assets, such as saved queries and Privilege Zone rules.
  
  Admins can install these components together in a single upload, streamlining the process of making an extension's assets available to users.

  - **Administrators:** Upload a bundle to [install an extension](/opengraph/extensions/manage) and its supported assets together.
  - **Users:** Explore extension data using its [saved queries](/analyze-data/explore/cypher-search/search) and apply its Privilege Zone [rules](/analyze-data/privilege-zones/rules).
  - **Extension developers:** Learn how to [package](/opengraph/developer/extension-bundles) an extension's schema and supported assets for administrators to install together.
</Update>

<Update label="SharpHound" description="Enhancement" tags={["Data Collection"]}>
  {/*BED-9763*/}
  ## Collect Azure VM IDs from Windows computers

  Correlate domain-joined Windows computers with their [Azure VM identity](/collect-data/sharphound-data-permissions#azure-vm-identity) using the Azure guest VM ID (`VmId`).

  When [`AzureRegistry`](/collect-data/ce-collection/sharphound-flags) collection is enabled, SharpHound reads the ID from domain-joined Windows computers and stores it in the Active Directory computer's `azvmid` property.
</Update>

<Update label="BloodHound" description="Enhancement" tags={["API"]}>
  {/*BED-10037*/}
  ## Faster object ID searches

  The [`/api/v2/search`](/reference/search/search-for-objects) endpoint now matches `objectid` values exactly, including uppercase and lowercase variants, while name searches remain fuzzy. 

  This improves search performance (most notably on the **Explore** page) and honors the result limit whether or not results are filtered by [Environment Targeted Access Control (ETAC)](/manage-bloodhound/auth/environment-targeted-access-control).
</Update>

<Update label="BloodHound" description="Enhancement" tags={["API"]}>
  {/*BED-10051*/}
  ## Accurate audit log counts for date ranges

  The [`/api/v2/audit`](/reference/audit/list-audit-logs) endpoint now applies the requested date range (including its documented 365-day default) to both the returned events and the `count`, so pagination totals match the results.

  <Note>
    It also returns HTTP 400 when the `after` value is later than the `before` value.
  </Note>
</Update>

<Update label="BloodHound" description="Enhancement" tags={["Explore"]}>

  ## Distinguish non-traversable graph edges

<Update label="BloodHound" description="Enhancement" tags={["Attack Paths"]}>
  {/*BED-9772, BED-9379, BED-8938, BED-8916*/}
  <img noZoom src="/assets/enterprise-edition-pill-tag.svg" alt="Applies to BloodHound Enterprise only" style={{ width: "25%" }}/>

  ## Findings Prioritization Improvements

  [Findings Prioritization](/analyze-data/findings/table-view#prioritize-findings) now considers proximity to Tier Zero alongside exposure, impact, and starting objects. Findings targeting objects in or near Tier Zero receive a stronger priority signal, helping you identify larger remediation opportunities.

  During analysis, BloodHound Enterprise uses a synthetic [Zone](/resources/nodes/zone) node to calculate the shortest traversable path from each finding's target to Tier Zero. Findings without a path to Tier Zero (or with a path beyond the maximum traversal depth) use a maximum-hop fallback and are de-prioritized.
</Update>
