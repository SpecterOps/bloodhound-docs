<Update label="BloodHound" description="New Feature" tags={["OpenGraph"]}>
  {/*BED-9897, BED-9497, BED-9498, BED-9322, BED-9319*/}
  ## Extension bundles

  An extension bundle packages an OpenGraph extension's schema with supported assets, such as saved queries and Privilege Zone rules.
  
  Admins can install these components together in a single upload, streamlining the process of making an extension's assets available to users.

  - **Administrators:** Upload a bundle to [install an extension](/opengraph/extensions/manage) and its supported assets together.
  - **Users:** Explore extension data using its [saved queries](/analyze-data/explore/cypher-search/search) and apply its Privilege Zone [rules](/analyze-data/privilege-zones/rules).
  - **Extension developers:** Learn how to [package](/opengraph/developer/extension-bundles) an extension's schema and supported assets for administrators to install together.
</Update>

<Update label="SharpHound" description="Enhancement" tags={["Data Collection"]}>
  {/*BED-9763*/}
  ## Collect Azure VM IDs from Windows computers

  SharpHound now collects the Azure VM guest ID (`VmId`) from Windows computers and stores it in the Active Directory computer's `azvmid` property. Use this value to correlate a domain-joined computer with its Azure VM identity.
</Update>

<Update label="BloodHound" description="Enhancement" tags={["Explore"]}>
  {/*BED-9130*/}
  ## Control graph direction and spacing

  Choose whether the Explore graph flows left, right, up, or down, and adjust horizontal and vertical spacing. These controls help you arrange complex graphs so their relationships are easier to inspect.
</Update>

<Update label="BloodHound" description="Enhancement" tags={["API"]}>
  {/*BED-10037*/}
  ## Faster object ID searches

  The `/api/v2/search` endpoint now matches `objectid` values exactly, including uppercase and lowercase variants, while name searches remain fuzzy. This improves search performance and honors the result limit whether or not results are filtered by ETAC.
</Update>

<Update label="BloodHound" description="Enhancement" tags={["API"]}>
  {/*BED-10051*/}
  ## Accurate audit log counts for date ranges

  The Audit Logs API now applies the requested date range, including its documented 365-day default, to both the returned events and the `count`, so pagination totals match the results. It also returns HTTP 400 when the `after` value is later than the `before` value.
</Update>

<Update label="BloodHound" description="Enhancement" tags={["PostgreSQL"]}>
  {/*BED-8495*/}
  ## Additional PostgreSQL storage optimization

  The PostgreSQL **Optimizing** phase now includes additional storage optimization steps. These steps help reclaim index bloat and keep graph query performance consistent over time.
</Update>

<Update label="BloodHound" description="Enhancement" tags={["PostgreSQL"]}>
  {/*BED-9997*/}
  ## Faster ingest reconciliation

  Improved graph edge cleanup uses index scans instead of table scans when deleting edges with a node. This reduces database work during ingest reconciliation and helps maintain ingest throughput.
</Update>

<Update label="BloodHound" description="Enhancement" tags={["PostgreSQL"]}>
  {/*BED-9971*/}
  ## Run PostgreSQL optimization independently

  The **Optimize** pipeline step no longer waits for an analysis run. This helps keep PostgreSQL statistics current and query plans efficient, including in environments where analysis has not run recently.
</Update>

<Update label="BloodHound" description="Enhancement" tags={["Post-Processing"]}>
  {/*BED-9943*/}
  ## More efficient post-processed edges

  All remaining post-processed edges now use the newer DCA processing path, retiring the legacy delete-and-recreate method. This reduces database churn and analysis time.
</Update>

<Update label="BloodHound" description="Enhancement" tags={["Attack Paths"]}>
  {/*BED-9772, BED-9379, BED-8938, BED-8916*/}
  <img noZoom src="/assets/enterprise-edition-pill-tag.svg" alt="Applies to BloodHound Enterprise only" style={{ width: "25%" }}/>

  ## Findings Prioritization Improvements

  Findings Prioritization now accounts for each finding's shortest traversable path from its target to Tier Zero. The score avoids multiplying by zero for impact or exposure, so findings with zero values are not incorrectly collapsed to the same score.

  BloodHound calculates hop count for open and accepted findings, using the configured maximum when no path is found or the path exceeds that maximum. Tier Zero membership is represented by a synthetic zone node for this analysis.
</Update>
