<Update label="BloodHound" description="Enhancement" tags={["Data Collection"]}>
  {/*BED-6182*/}
  ## ADCS ESC11 support

  BloodHound now ingests and analyzes the `RPCEncryptionEnforced` property collected from Active Directory Certificate Services (ADCS) certificate authorities.
  
  This allows BloodHound to identify certificate authorities that may be vulnerable to ESC11 and model vulnerable RPC enrollment paths with the new [CoerceAndRelayNTLMToADCSRPC](/resources/edges/coerce-and-relay-ntlm-to-adcs-rpc) edge. See the [EnterpriseCA node](/resources/nodes/enterprise-ca) for details about the collected property.

  <img noZoom src="/assets/enterprise-edition-pill-tag.svg" alt="Applies to BloodHound Enterprise only" style={{ width: "25%" }}/>

  BloodHound Enterprise also reports a **Tier Zero Coerce And Relay NTLM To ADCS RPC** finding for the new edge.

  <Note>
    **Dependency**

    This enhancement requires SharpHound v2.18.0 to collect the corresponding [ADCS ESC11 data](/resources/release-notes/2026-11-16#adcs-esc11-collection).
  </Note>
</Update>

<Update label="BloodHound" description="Enhancement" tags={["Data Collection"]}>
  {/*BED-6176*/}
  ## ADCS ESC16 support

  BloodHound now ingests and analyzes the `DisabledExtensions` setting collected from certificate authorities.
  
  This allows BloodHound to identify certificate authorities that disable the security extension and may be vulnerable to ESC16, represented by the [ADCSESC16](/resources/edges/adcs-esc16) edge. See the [EnterpriseCA node](/resources/nodes/enterprise-ca) for details about the collected property.

  <img noZoom src="/assets/enterprise-edition-pill-tag.svg" alt="Applies to BloodHound Enterprise only" style={{ width: "25%" }}/>

  BloodHound Enterprise also reports a **Non-Tier Zero Principals With ADCS ESC16 Privileges** finding for the new edge.

  <Note>
    **Dependency**

    This enhancement requires SharpHound v2.18.0 to collect the corresponding [ADCS ESC16 data](/resources/release-notes/2026-11-16#adcs-esc16-collection).
  </Note>
</Update>

<Update label="SharpHound" description="Enhancement" tags={["Data Collection"]}>
  {/*BED-6182*/}
  ## ADCS ESC11 collection

  Collect ADCS ESC11 data with SharpHound v2.18.0.

  SharpHound collects the certificate authority's RPC encryption setting and exposes it as `RPCEncryptionEnforced` for BloodHound analysis.

  See [ADCS ESC11 support](/resources/release-notes/2026-11-16#adcs-esc11-support) to learn how BloodHound uses this data.
</Update>

<Update label="SharpHound" description="Enhancement" tags={["Data Collection"]}>
  {/*BED-6176*/}
  ## ADCS ESC16 collection

  Collect ADCS ESC16 data with SharpHound v2.18.0.

  SharpHound collects the certificate authority's `DisableExtensionList` setting and reports whether the value was collected successfully.

  See [ADCS ESC16 support](/resources/release-notes/2026-11-16#adcs-esc16-support) to learn how BloodHound uses this data.
</Update>

<Update label="OpenHound" description="Enhancement" tags={["GitHub"]}>
  ## GitHub collection

  - {/*BED-10447*/} Collect GitHub enterprise identity providers and external identities for enterprises that use OIDC federation, alongside the existing SAML support. The graph now represents OIDC providers and their identity relationships.
  - {/*BED-10454*/} Inspect the GitHub App installation used for enterprise collection, including its granted permissions. The collector now represents enterprise-level installations as `GH_AppInstallation` nodes in addition to organization installations.
  - {/*BED-10295*/} See who registered a GitHub App and whether the registration belongs to the collected tenant or a third party. Registration ownership is distinct from where the app is installed.
</Update>

<Update label="OpenHound" description="Enhancement" tags={["Okta"]}>
  {/*BED-10093, BED-10053, BED-10052, BED-10007*/}
  ## Okta collection

  - Limit application-user and MFA collection to reduce request volume in large organizations. See [Large Environment Settings](/openhound/collectors/okta/large-environment-settings) for collection scope options.
  - Tune request concurrency, rate-limit handling, and page sizes to make better use of Okta API capacity. See [Large Environment Settings](/openhound/collectors/okta/large-environment-settings) for configuration details and [Performance Telemetry](/openhound/collectors/okta/performance-telemetry) to diagnose collection performance.
  - Inspect Entity panel details for collected relationships to investigate their composition.
</Update>

<Update label="BloodHound" description="Enhancement" tags={["OpenGraph"]}>
  {/*BED-10091*/}
  ## Privilege Zone rule settings

  Keep your chosen enabled state for Privilege Zone rules when an extension bundle is updated.

  The bundle's `enabled` default now applies when a rule is created, while updates preserve an administrator's existing choice unless the rule becomes always enabled.

  Administrators can learn more in [Update an extension](/opengraph/extensions/manage#update-an-extension). Extension developers can learn more in [Privilege Zone rules for extension bundles](/opengraph/developer/extension-bundles#privilege-zone-rules).
</Update>

<Update label="BloodHound" description="Enhancement" tags={["Attack Paths"]}>
  {/*BED-9834, BED-9963*/}
  ## Findings API enhancements

  <img noZoom src="/assets/enterprise-edition-pill-tag.svg" alt="Applies to BloodHound Enterprise only" style={{ width: "25%" }}/>

  Use [`GET /api/v2/attack-paths/findings`](/reference/attack-paths/list-attack-path-findings) to filter findings by a principal object's ID with `principal_object_id`. The filter matches findings where the object is either the source or target principal.

  Use the `is_regression` field to identify unarchived findings that match a previously archived, remediated finding by type, name, environment, zone, and principal identity.
</Update>

<Update label="BloodHound" description="Enhancement" tags={["Attack Paths"]}>
  ## Findings Table action menu

  <img noZoom src="/assets/enterprise-edition-pill-tag.svg" alt="Applies to BloodHound Enterprise only" style={{ width: "25%" }}/>

  The **Findings Table** [action menu](/analyze-data/findings/table-view#take-action-on-a-finding) allows you to perform actions on selected findings directly from the table:

  - {/*BED-9148*/} Accept selected findings directly from the **Findings Table** to temporarily mute findings that you will not act on.

  - {/*BED-9687*/} Mark selected findings as **In Progress** from the **Findings Table** to indicate that you are actively working on them.

  <FeatureFlagNote />
</Update>

<Update label="BloodHound" description="Enhancement" tags={["Attack Paths"]}>
  {/*BED-9676, BED-10262*/}
  ## Findings Table status management and remediation

  <img noZoom src="/assets/enterprise-edition-pill-tag.svg" alt="Applies to BloodHound Enterprise only" style={{ width: "25%" }}/>

  An updated findings API supports setting findings to **Accepted** or **In progress** in the **Findings Table** and enables the new remediation workflow. The update is off by default and must be enabled by SpecterOps.

  If you use an integration or custom automation that consumes findings, the change may affect it. Contact your account team to enable the update so we can review your integration and plan a safe transition.
</Update>
