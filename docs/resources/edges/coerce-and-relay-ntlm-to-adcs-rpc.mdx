This edge indicates that an attacker with "Authenticated Users" access can trigger SMB-based coercion from the target computer to their attacker-controlled host via NTLM. The authentication attempt from the target computer can then be relayed to an ESC11-vulnerable RPC enrollment endpoint of an Active Directory Certificate Services (ADCS) enterprise CA server. This allows the attacker to obtain a certificate enabling domain authentication as the target computer.

The ESC11 attack differs from the HTTP-based ADCS relay attack (ESC8) because it targets RPC endpoints instead of web enrollment endpoints. For ESC11 to succeed, the Enterprise CA must have RPC encryption disabled - specifically, the `IF_ENFORCEENCRYPTICERTREQUEST` CA flag must be turned off. In BloodHound, this configuration is revealed by the "RPC Encryption Enforced" (`rpcencryptionenforced`) property on the EnterpriseCA node.

Click on **Relay Targets** to view vulnerable enterprise CA servers that enable certificate enrollment for the target computer via RPC endpoints.

## Abuse Info

<NtlmRelayGuidance />

### Linux

<Steps>
  <Step title="Start the Relay Server">
    The NTLM relay can be executed with [ntlmrelayx.py](https://github.com/fortra/impacket/blob/master/examples/ntlmrelayx.py). To relay to the enterprise CA via RPC endpoints and enroll a certificate, specify the RPC endpoint as the target and use the arguments:

    ```bash
    -t rpc://<CA_IP> -rpc-mode ICPR -icpr-ca-name <CA_NAME> -smb2support
    ```
  </Step>
  <Step title="Coerce the Target Computer">
    <NtlmCoercionSmb />
  </Step>
  <Step title="Perform Certificate Authentication">
    Authenticate using the certificate obtained as the target principal, for example by using [Certipy](https://github.com/ly4k/Certipy).
  </Step>
</Steps>

### Windows

<Steps>
  <Step title="Start the Relay Server on Linux">
    There is currently no publicly available Windows tool that supports relaying NTLM authentication to an AD CS RPC enrollment endpoint. Start the relay server on a Linux host using [ntlmrelayx.py](https://github.com/fortra/impacket/blob/master/examples/ntlmrelayx.py). To relay to the enterprise CA via RPC and enroll a certificate, specify the RPC endpoint as the target and use the following arguments:

    ```bash
    -t rpc://<CA_IP> -rpc-mode ICPR -icpr-ca-name <CA_NAME> -smb2support
    ```
  </Step>
  <Step title="Coerce the Target Computer">
    <NtlmCoercionSmb />
  </Step>
  <Step title="Perform Certificate Authentication">
    Authenticate using the certificate obtained as the target principal, for example by using [Rubeus](https://github.com/GhostPack/Rubeus).
  </Step>
</Steps>
