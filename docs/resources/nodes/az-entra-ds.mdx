An `AZEntraDS` node represents a `Microsoft.AAD/domainServices` Azure Resource Manager resource. Microsoft Entra Domain Services (Entra DS) provides managed domain controllers and synchronizes selected identities and credential material from Microsoft Entra ID into the managed domain.

AzureHound collects this node as part of the `az-rm` collection scope. The collector requires `Microsoft.AAD/domainServices/read`. Collecting direct role assignments against the resource additionally requires `Microsoft.Authorization/roleAssignments/read`.

<Note>
AzureHound does not collect the Secure LDAP public certificate, certificate expiration, or certificate thumbprint from this resource.
</Note>

## Relationships

AzureHound and BloodHound create the following containment relationship:

```cypher
(:AZResourceGroup)-[:AZContains]->(:AZEntraDS)
```

BloodHound also creates direct Azure RBAC relationships to the node for supported role assignments whose scope exactly matches the domain service resource:

| Azure role | BloodHound relationship |
| --- | --- |
| Owner | [`AZOwner`](/resources/edges/az-owner) |
| User Access Administrator | [`AZUserAccessAdministrator`](/resources/edges/az-user-access-administrator) |
| Contributor | [`AZContributor`](/resources/edges/az-contributor) |
| Domain Services Contributor | [`AZEntraDSContributor`](/resources/edges/az-entra-ds-contributor) |

As with other Contributor relationships, inherited general Azure roles are not duplicated as direct edges to every descendant resource. Assignments collected on a management group, subscription, or resource group reach `AZEntraDS` through [`AZContains`](/resources/edges/az-contains) paths. Domain Services Contributor is currently collected only when assigned directly to the managed-domain resource, so parent-scoped assignments of that service-specific role are not represented. The raw `AZContributor` and `AZEntraDSContributor` relationships are not sufficient by themselves to prove control of Entra DS synchronization or security settings.

BloodHound post-processing creates a traversable [`AZManageEntraDS`](/resources/edges/az-manage-entra-ds) relationship only when one effective principal has Contributor or Domain Services Contributor over this resource and also has both Application Administrator and Groups Administrator in Entra ID:

```cypher
(:AZUser|AZGroup|AZServicePrincipal)-[:AZManageEntraDS]->(:AZEntraDS)
```

BloodHound corroborates the resource's normalized `domainName` with the tenant's synchronized `AAD DC Administrators` group and the AD domain SID. It then creates a non-traversable [`EntraDSFor`](/resources/edges/entra-ds-for) relationship from the resource to the AD domain. If that domain has a `Domain Users` group with RID 513, BloodHound emits [`ManageEntraDSSync`](/resources/edges/manage-entra-ds-sync) from every qualified principal to that group. This edge is independent of the resource's current `syncscope` and `filteredsyncenabled` properties.

When `syncscope` is `All` and `filteredsyncenabled` is `true`, BloodHound separately emits [`ManageEntraDSSyncFilter`](/resources/edges/manage-entra-ds-sync-filter) from the tenant-local Entra DS Domain Controller Services service principal to the same `Domain Users` group.
