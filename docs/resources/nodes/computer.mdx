## Node properties

<NodePropertiesTableGuide />

| Property key and value type | Entity panel display name | Description |
| --- | --- | --- |
| — | Tier Zero | Whether BloodHound classifies the object as Tier Zero. This UI status is not a stored `highvalue` node property. |
| `displayname`<br />`string` | Display Name | The display name for the object. |
| `objectid`<br />`string` | Object ID | Example: `S-1-5-21-…-500`. The object's security identifier (SID), a unique identifier in the directory. |
| `isaclprotected`<br />`boolean` | ACL Inheritance Denied | Whether the object’s discretionary access control list (DACL) blocks inherited access control entries (ACEs). |
| `admincount`<br />`boolean` | Admin Count | Indicates whether Active Directory has marked the account for protected-account handling. The flag can remain after privileged group membership is removed. |
| `adminsdholderprotected`<br />`boolean` | AdminSDHolder Protected | The authoritative security descriptor of this object matches that of the AdminSDHolder container and is therefore protected by it. AdminSDHolder is a security descriptor template that the ProtectAdminGroups background task stamps on protected objects. |
| `unconstraineddelegation`<br />`boolean` | Allows Unconstrained Delegation | Whether the account permits unconstrained Kerberos delegation. See [Kerberos delegation background](https://blog.harmj0y.net/redteaming/another-word-on-delegation/). |
| `whencreated`<br />Unix epoch seconds | Created | Example: `1568630538`. The time when the object was created in the directory. |
| `description`<br />`string` | Description | The contents of the `description` field for the object. |
| `enabled`<br />`boolean` | Enabled | Whether the computer object is enabled. |
| `haslaps`<br />`boolean` | LAPS Enabled | Whether LAPS is running on the computer. This is determined by checking whether the associated MS LAPS properties are populated on the computer object. |
| `lastlogon`<br />Unix epoch seconds | Last Logon | The last time the domain controller you got this data from handled a logon request for the object. Attribute `lastLogon`. |
| `lastlogontimestamp`<br />Unix epoch seconds | Last Logon (Replicated) | The replicated, approximate logon time from the directory’s `lastLogonTimestamp` attribute. Updates are periodic, so this value can lag recent logons. |
| `operatingsystem`<br />`string` | Operating System | The operating system running on the computer, according to the corresponding property on the object in the directory. |
| — | Is Owned | BloodHound Community Edition: whether the object is marked as owned. This UI status is not a stored `owned` node property. |
| `pwdlastset`<br />Unix epoch seconds | Password Last Set | The human-readable date for when the user’s password last changed. This is stored internally in Unix epoch format |
| `trustedtoauth`<br />`boolean` | Trusted For Constrained Delegation | Reports the `TRUSTED_TO_AUTH_FOR_DELEGATION` flag, which enables constrained delegation with protocol transition. This flag does not cover Kerberos-only constrained delegation.<br /><br />Find this in Active Directory Users and Computers: View → Advanced Features → account Properties → Attribute Editor → `userAccountControl`; inspect flag 0x1000000. |
| `sidhistory`<br />`string[]` | SID History | Example: `["S-1-5-21-…"]`. Additional security identifiers retained on this account, commonly after migration from another domain.<br /><br />Find this in Active Directory Users and Computers: View → Advanced Features → account Properties → Attribute Editor → `sIDHistory`. |
| `supportedencryptiontypes`<br />`string[]` | Supported Kerberos Encryption Types | Example: `["AES256-CTS-HMAC-SHA1-96"]`. The Kerberos encryption types advertised by this account for service-ticket encryption.<br /><br />Find this in Active Directory Users and Computers: View → Advanced Features → account Properties → Attribute Editor → `msDS-SupportedEncryptionTypes`. |
| `ntlmminserversec`<br />`integer` | NTLM Minimum Server Session Security | The collected bitmask of minimum NTLM session-security requirements for servers, such as NTLMv2 session security and 128-bit encryption.<br /><br />Find this in Local Security Policy on the computer: Security Settings → Local Policies → Security Options → Network security: Minimum session security for NTLM SSP based (including secure RPC) servers. |
| `ntlmminclientsec`<br />`integer` | NTLM Minimum Client Session Security | The collected bitmask of minimum NTLM session-security requirements for clients, such as NTLMv2 session security and 128-bit encryption.<br /><br />Find this in Local Security Policy on the computer: Security Settings → Local Policies → Security Options → Network security: Minimum session security for NTLM SSP based (including secure RPC) clients. |
| `lmcompatibilitylevel`<br />`integer` | LAN Manager Compatibility Level | The collected LAN Manager authentication level, which controls LM, NTLM, and NTLMv2 authentication behavior.<br /><br />Find this in Local Security Policy on the computer: Security Settings → Local Policies → Security Options → Network security: LAN Manager authentication level. |
| `ldapsepa`<br />`boolean` | LDAPS Extended Protection | Reports the LDAPS channel-binding test result. TRUE means authentication with invalid channel bindings did not succeed; it does not prove that channel binding is required for every client.<br /><br />Find this in Local Security Policy on the domain controller: Security Settings → Local Policies → Security Options → Domain controller: LDAP server channel binding token requirements. |

## Additional output property

SharpHound may add the lowercase Azure guest VM identifier as the `azvmid` property when it can read `HKLM\SOFTWARE\Microsoft\Windows Azure\VmId` from the computer.
