Nodes represent identities, resources, and other objects from Active Directory, Microsoft Entra ID, Azure, and other data sources. Select a node in **Explore** and expand **Object Information** in its entity panel to inspect its properties.

Property references distinguish the **property key** used by the API and Cypher from the **entity panel display name**. For example, on a User node, `passwordnotreqd` is the key, while **Password Not Required** is its display name. A directory attribute such as `userAccountControl` is a separate source name. API-only references and computed UI statuses are identified so they are not mistaken for stored graph properties.

Nodes are part of the graph construct, and are represented as circles with an illustration.

For example, the image below shows three [User](/resources/nodes/user) nodes (left side) connected to one [Group](/resources/nodes/group) node (right side). The nodes are connected via the [MemberOf](/resources/edges/member-of) edge. Read more about edges in the article [About BloodHound Edges](/resources/edges/overview).

Each article in this section documents an individual node and each contains:

* **Node Properties:** Names and descriptions of properties the node can contain. Properties are found by expanding Object Information within the Entity Panel.
* **References:** External references that contain more details about the node.

Property keys are case-sensitive. Use the key exactly as documented, even when its spelling differs from the display name or source directory attribute.
