Use this page to identify whether a Managed Collection problem originates from beta availability, AWS authentication, permissions, scheduling, or the Managed Collection service.

The BloodHound Enterprise user interface supports collection plan save and queue operations, but the feature is tenant-gated and collection processing occurs in the managed service. Record the plan name, time of the attempt, visible result, and error text before you contact your SpecterOps account team.

## Check beta availability

If **Managed Collection** is not present under **Administration** > **Data Collection**, the `managed_openhound_collection` feature is not enabled for your tenant.

The feature is SpecterOps-managed, disabled by default, and not user-updatable. Contact your account team to confirm beta access.

## Understand beta health signals

The beta exposes collection plan activity and the latest job result in the **Collection Plans** page. It does not expose a separate managed-worker health panel.

If several plans stop producing results, provide the plan names and expected run times to your SpecterOps account team so they can review collection health and detailed logs.

## Review collection results

On **Collection Plans**, inspect the plan tile and its schedule:

| Status | Meaning |
| --- | --- |
| **No schedule set** | The plan will not create recurring jobs. |
| **Not run yet** | The plan has no completed collection history. |
| **Success** | The latest job completed successfully. |
| **Warning** | The latest job completed only partially. Select **History** to inspect the result and failure reason. |
| **Failed** | The latest job ended with an error. The current tile shows the outcome and timestamp, but not the full failure metadata. |
| **Cancelled** | The latest job was cancelled before completion. |
| **Disabled** | The schedule is paused. |

Select **History** on the plan tile to open job history. Use the Run Results filter to narrow the list, sort by Started at or Completed at, and hover a failed or warning result to view its failure reason.

If the page cannot load a schedule or latest result, use the page's **Retry** action. If the problem persists, record the plan name and the error message.

## Resolve common issues

<AccordionGroup>
  <Accordion title="The AWS credential is rejected">
    **Likely cause:** The access key ID or secret access key is incorrect, inactive, expired, or not available to the Managed Collection service.

    **Action:** Verify the key pair in AWS without sharing the secret value and confirm that the key is active. If the credential must be replaced, follow [Replace a credential](/collect-data/enterprise-collection/managed-collection/configure#replace-a-credential). Deleting the old plan does not revoke the old AWS key or automatically delete its secret reference.
  </Accordion>

  <Accordion title="The configuration JSON is rejected">
    **Likely cause:** The **Configuration** field contains malformed JSON or a valid JSON value that is not an object, such as an array, string, number, or `null`.

    **Action:** Follow [Enter the configuration](/collect-data/enterprise-collection/managed-collection/configure#configure-a-collection-plan) to correct the JSON object and validation message. If the JSON is accepted but collection fails, review the AWS collector schema, collection scope, and required permissions. Do not include credentials or tokens in the configuration.
  </Accordion>

  <Accordion title="The collection lacks AWS permissions">
    **Likely cause:** The collection principal cannot read one or more AWS services or accounts in the configured scope.

    **Action:** Compare the plan's scope with the principal's policy. Grant only the read permissions required by the scope, following [Configure AWS permissions](/openhound/collectors/aws/configure-permissions), then create a new plan if the credential also changed.
  </Accordion>

  <Accordion title="The plan has no collection results">
    **Likely cause:** The plan has no schedule, the schedule is disabled, or the scheduled job has not been processed yet.

    **Action:** Confirm that the plan displays an active schedule and that it is not marked **Disabled**. If the schedule is correct and no result appears after the scheduled window, record the plan name and expected run time and contact your SpecterOps account team.
  </Accordion>

  <Accordion title="The Managed Collection service appears unavailable">
    **Likely cause:** The managed worker is not processing jobs, or several plans are affected by a service-level problem. You can see collection plan results, not the managed worker's health state or detailed logs.

    **Action:** Confirm that the affected plans have active schedules and record the expected run times. If several plans are affected, contact your SpecterOps account team with the affected plan names and timestamps so they can review service health and detailed logs.
  </Accordion>

  <Accordion title="The schedule time is unexpected">
    **Likely cause:** The form displays local time and the GMT offset, while the recurrence is stored in UTC.

    **Action:** Follow [Configure a schedule](/collect-data/enterprise-collection/managed-collection/configure#configure-a-collection-plan) to review the detected timezone, GMT offset, and saved recurrence. Select the desired start time again and save the plan.
  </Accordion>

  <Accordion title="The collection is incomplete or shows Warning">
    **Likely cause:** The AWS principal does not have read access to all resources in the configured scope, the scope excludes the resources you expect, or the latest job completed only partially.

    **Action:** Confirm the AWS account or organization scope and review the required read-only policy. Use the AWS permissions page to check service-specific permissions, select **History**, and inspect the failure reason for the warning or failed result. Review the next collection result after correcting the scope or permissions.
  </Accordion>

  <Accordion title="The credential is close to expiration">
    **Likely cause:** The beta does not provide proactive credential or certificate expiry warnings.

    **Action:** Track the AWS key lifecycle in your organization's credential-management process. Create a replacement plan before the key expires, confirm a successful result, disable or delete the old key in AWS, and follow the SpecterOps-provided process for deleting the old secret reference.
  </Accordion>

  <Accordion title="A network allowlist blocks collection">
    **Likely cause:** Your AWS or network controls do not allow the Managed Collection traffic path.

    **Action:** Request the current Managed Collection egress IP range and change notification process from your SpecterOps account team. Do not infer the range from a self-deployed collector's address.
  </Accordion>

  <Accordion title="A save or run action does not complete">
    **Likely cause:** The Managed Collection beta is not enabled for the tenant, the action is still being rolled out, or the profile, schedule, or queue request failed.

    **Action:** Retry once. If the action still fails, capture the visible notification, plan name, and timestamp. Contact your SpecterOps account team. Do not include credential values in the report.
  </Accordion>
</AccordionGroup>

## Preserve evidence for support

Provide the following non-secret details when you request support:

- Tenant name
- Collection plan name
- AWS collection scope
- Expected schedule and detected timezone
- Time of the attempted or scheduled run
- Result shown in BloodHound Enterprise and the complete visible error text

<Warning>
  Do not provide an access key secret, secret access key, or any other credential material.
</Warning>
